# Research

* [Ungrammar as AST spec for Rocci and Rocdown](ungram-ast.md) - Exploratory recommendation: ungrammar as the tree spec for both languages; generate owned AST structs; do not generate scanners. Implementation plan: [ungram AST codegen](../plans/ungram-ast.md). Not shipped.
* [Optional request argument on Rocci service handlers](optional-handler-request.md) - Shipped: one-parameter `@on` lists inject unused `_request` at lowering so dispatch stays `handler!(context, request)`. Follow-ons (dispatch arity, request as a handler-input field) are exploratory and not shipped.
* [Efficient publishing of Rocdown sites and Rocci apps](efficient-publishing.md) - Build-once artifact model: static `dist/` needs only a file server; keep native apply because basic-cli/webserver have no wasm32; Roc `--target` can emit Linux musl from macOS for process binaries. Implementation plan: [efficient publishing](../plans/efficient-publishing.md). Exploratory; not approved.
* [Hybrid Rocdown islands for CDN-static sites](hybrid-rocdown-islands.md) - Exploratory research: CDN-static HTML with dynamic Rocci components backed by a rocci/rocdown HTTP service. Implementation plan: [hybrid Rocdown islands](../plans/hybrid-rocdown-islands.md) (rebase onto main's `:name` forest required). Not shipped.
* [Generalized Rocdown block model](generalized-rocdown-block-model.md) - Article blocks as `:name[params]` with `{{ }}` bodies. Source spelling shipped; original record still exploratory on leftover open questions. Follow-on: [custom block schemas and renderers](rocdown-block-renderers.md).
* [Custom Rocdown block schemas and renderers](rocdown-block-renderers.md) - Design research for `:kind` as a Rocci function interface, constrained children, site-selected painters, debug fallback. Worked `:callout` sketches and why named Roc structs are not the v1 schema source. Overlay is in the crate; leftover `@block` / heading Prose are not. Plan: [custom block schemas and renderers](../plans/rocdown-block-renderers.md). Post-landing comparison: [landed renderers vs related systems](rocdown-block-renderers-comparison.md).
* [Landed Rocdown block renderers compared with related systems](rocdown-block-renderers-comparison.md) - Exploratory scores of the shipped KindSpec plus theme pack against Markdoc, MDX, Nuxt, Gutenberg, Typst, and related systems. Follow-on: authoring DX, authorable surface, expressability ceiling, and stack-consistency fractures. Remaining gaps: custom-kind child policy, typed lists into parent painters, `@block`, heading Prose.
* [Desktop host chrome versus Rocci inspector UI](desktop-host-chrome-and-inspector-ui.md) - Split wry overlay chrome (HTML/CSS/JS) from preview-origin Rocci panels for compiler metrics and similar richer UI.
* [Extended preview-window inspector](preview-inspector.md) - Dock/tabs/console shells landed; Source still does not scroll and overlay dock chrome covers tabs. Remaining work: [investigate and repair the preview inspector](../plans/preview-inspector-repair.md). Exploratory.
* [Branding and community foundation](branding-community-foundation.md) - Exploratory masterbrand, naming, SEO, visual-identity, and public-preview community research.
* [Repository hosting for Rocci's distributed governance](repository-hosting-and-distributed-governance.md) - GitHub and Tangled comparison for public launch, contributor workflow, infrastructure ownership, and future shared authority.
* [Tangled as canonical host with a GitHub macOS CI mirror](tangled-hosting.md) - Inverse topology for a near-term public open-source clone: Tangled owns git, issues, PRs, and Linux CI; GitHub remains a SHA-faithful mirror for `macos-latest` Actions. No shipped orgs; grouping is sibling repos under one handle. Implementation plan: [Tangled hosting](../plans/tangled-hosting.md). Exploratory; not approved.
* [OKF preview compile and render cost](okf-compile-render-cost.md) - After load-performance Phases 1–4, first-open and Markdown-edit `rocci-okf run` was dominated by Roc `compile` and `render`. Phases 1–3 and 6 of the [implementation plan](../plans/okf-compile-render-cost.md) are in this tree; [results snapshot](../status/okf-compile-render-cost.md). Follow-on: [deferred compile/render follow-ons](../plans/okf-compile-render-follow-ons.md). Exploratory; not shipped.
* [Rocci components in the generation pipeline](rocci-components-in-generation.md) - Evidence for moving demonstrated HTML chrome into Rocci, native subprocess versus Wasmtime hosts, two-tier renderer caching, and glue as a later native host.
* [State-of-the-art OKF tools and workflows](okf-tools-and-workflows.md) - Portable Markdown, agent-native operations, curation, review, retrieval, and authenticated serving lessons.
* [Rocdown report authoring friction](rocdown-report-authoring-friction.md) - Evidence and priorities for figures, citations, assets, report presentation, and export.
* [Mobile chrome for OKF, Rocdown, and rocci.dev](mobile-chrome.md) - Code-backed inventory: default Rocdown theme has a no-JS menu; rocci.dev hides the docs sidebar without replacement; OKF nests Home/Review inside a TOC that phone CSS discards. Implementation plan: [mobile chrome](../plans/mobile-chrome.md). Exploratory; not shipped.
* [Native macOS app for rocci-browser; drop the TUI](rocci-browser-macos-app.md) - Finder-launchable ad-hoc `Rocci Browser.app` around the shipped `preview()` host; delete the crossterm picker; keep headless `open --no-window`. Does not reuse `rocci bundle` or embed adapters. Implementation plan: [macOS app and TUI removal](../plans/rocci-browser-macos-app.md). Exploratory; not approved.
* [Dedicated rocci-browser CLI and desktop host](rocci-browser.md) - Product-blind project registry and two-stage fuzzy picker (Enter opens a target, Tab lists documents) via out-of-process adapters; complements the shared preview window without plugins on `rocci` / `rocdown`. Implementation plan: [rocci-browser](../plans/rocci-browser.md). TUI front withdrawn; `.app` packaging is [macOS app research](rocci-browser-macos-app.md). Exploratory; not approved.

Dated historical research reports remain available under [`archive/reports/`](../../archive/reports/) and are accounted for in the migration matrix.
